# nginx-pool

A self-hosted multi-user nginx reverse-proxy manager.  
One command (`nginx-pool add alice blog.example.com`) provisions a full virtual-host, wires it into nginx, and optionally issues or extends a Let's Encrypt certificate.  A separate `reverse` sub-command manages arbitrary upstream reverse-proxies (replacing hand-crafted `ProxyPass` entries).

---

## Architecture

```
                 Internet
                    │
              nginx (443 / 80)
                    │
          ┌─────────┴──────────┐
          │  pool.conf (catch-all) │
          │  reverses.conf         │  ← managed by nginx-pool reverse
          │  conf.d/*.conf         │  ← GitLab etc.
          └─────────┬──────────┘
                    │
         Four-step lookup chain:
         1. user.map       $host → $pool_user
         2. domain.map     $host → /home/$user/www/<fs-path>
         3. Unix socket    /home/$user/www/<fs-path>.sock
         4. Fallback       /home/nginx/www/localhost/ → /usr/share/nginx/html
```

### Map files (live in `/etc/nginx/`)

| File | Purpose |
|------|---------|
| `user.map` | `$host → $pool_user` |
| `domain.map` | `$host → canonical FS path` |
| `ssl_cert.map` | `$ssl_server_name → cert-family name` |
| `lock.map` | locked domains → maintenance page |
| `port_http.map` / `port_https.map` | Docker / non-socket backends |
| `legacy.map` | old-domain → new-domain redirects |

All map files are rebuilt by `nginx-pool` sub-commands and copied to `/etc/nginx/` on every change.

### Repository layout

```
/var/www/nginx/
├── Makefile                  # make install / make reload
├── nginx.conf                # top-level nginx config (generated from template)
├── nginx.conf.template
├── conf.d/
│   ├── pool.conf             # catch-all multi-user vhost (generated)
│   ├── pool.conf.template
│   └── reverses.conf         # auto-generated by nginx-pool reverse apply
├── bin/
│   └── nginx-pool            # the CLI (also installed to /usr/local/bin/)
├── ssl_cert.map              # version-controlled copy of the SSL map
└── reverses/
    └── *.rev                 # one file per reverse-proxy entry
```

`make install` generates configs from templates and copies everything to `/etc/nginx/`.

## Installation

```bash
cd /var/www/nginx
make install        # generates pool.conf, copies to /etc/nginx/, reloads nginx
```

For a fresh server also run `make nginx` (installs nginx + certbot) and `make php`.

## Pool vhosts

### Add a vhost

```bash
# Bare domain — nginx-pool creates /home/alice/www/com.example.blog/
nginx-pool add alice blog.example.com

# With an existing certificate family
nginx-pool add alice blog.example.com --master example.com

# Extend the family cert to include this domain, then add
nginx-pool add alice blog.example.com --master example.com --extend-cert

# Short-path app under pool.glitchr.dev
nginx-pool add georges myapp --master pool.glitchr.dev
# → https://georges.pool.glitchr.dev/myapp/
```

### Remove a vhost

```bash
nginx-pool remove alice blog.example.com   # remove one domain
nginx-pool remove alice                    # remove all of alice's vhosts
```

### Lock / maintenance mode

```bash
nginx-pool lock   alice blog.example.com
nginx-pool unlock alice blog.example.com
```

### List vhosts

```bash
nginx-pool list             # all active vhosts
nginx-pool list --local     # include *.localhost entries
nginx-pool list --backend   # show socket/port backend paths
```

### Fix permissions

```bash
nginx-pool acl alice                      # fix ACL for all of alice's vhosts
nginx-pool acl alice blog.example.com     # fix one vhost
```

## SSL certificates

### Issue / extend a cert for an existing domain

```bash
nginx-pool cert blog.example.com
nginx-pool cert blog.example.com --master example.com    # join a cert family
```

`--extend-cert` (available on `add`) reads the current SANs from the existing cert using `openssl x509` before calling certbot, so no domains are lost.

### List certs

```bash
nginx-pool certs                    # all certs on this server
nginx-pool certs alice              # only certs covering alice's domains
nginx-pool certs --simple           # compact one-line-per-cert output
```

### Renew (cron-safe)

```bash
nginx-pool renew
```

### Rebuild the SSL map

```bash
nginx-pool ssl-map
```

The SSL map (`ssl_cert.map`) tells nginx which certificate to serve per SNI hostname. It is rebuilt automatically by `cert`, `add`, and `ssl-map`.

## Reverse proxies

The `reverse` sub-command manages arbitrary upstream proxies — an nginx equivalent of Apache `ProxyPass`.  Entries are stored as small `.rev` files in `/var/www/nginx/reverses/` and compiled into `/etc/nginx/conf.d/reverses.conf` by `reverse apply`.

### Add / update

```bash
nginx-pool reverse add <domain> <upstream> [options]
```

| Option | Default | Description |
|--------|---------|-------------|
| `--cert <name>` | auto-detected | cert family to use for TLS |
| `--no-ssl-verify` | off | skip upstream TLS verification (self-signed certs) |
| `--index` | off | allow search-engine indexing (default: `X-Robots-Tag: noindex`) |
| `--no-ws` | on | disable WebSocket upgrade headers |
| `--no-apply` | — | save entry but don't rebuild conf / reload nginx |

**Examples:**

```bash
# Internal server with self-signed cert
nginx-pool reverse add carl.glitchr.dev    https://192.168.92.3        --no-ssl-verify --cert carl.glitchr.dev
nginx-pool reverse add nas.glitchr.dev     https://192.168.92.3:5001   --no-ssl-verify --cert carl.glitchr.dev

# Local services
nginx-pool reverse add docker.glitchr.dev  http://127.0.0.1:9000       --cert pool.glitchr.dev
nginx-pool reverse add amqp.glitchr.dev    http://127.0.0.1:15672       --cert pool.glitchr.dev
nginx-pool reverse add gitlab.glitchr.dev  http://127.0.0.1:2443        --cert gitlab.glitchr.dev

# WebSocket service (ws upgrade is on by default)
nginx-pool reverse add jupyter.glitchr.dev http://127.0.0.1:8888        --cert pool.glitchr.dev

# Disable WS if upstream doesn't support it
nginx-pool reverse add myapp.glitchr.dev   http://127.0.0.1:3000 --no-ws
```

### Remove

```bash
nginx-pool reverse remove carl.glitchr.dev
```

### Show details

```bash
nginx-pool reverse show carl.glitchr.dev
```

### List

```bash
nginx-pool reverse list              # all entries
nginx-pool reverse list carl         # filter — matches domain or cert name
```

### Rebuild conf + reload nginx

```bash
nginx-pool reverse apply
```

This is called automatically by `add` and `remove` unless `--no-apply` was passed.

### Entry file format (`.rev`)

```
domain=carl.glitchr.dev
upstream=https://192.168.92.3
cert=carl.glitchr.dev
ssl_noverify=1
noindex=1
ws=1
```

Files live in `/var/www/nginx/reverses/` and are version-controlled with the rest of the repo.

## Typical workflow

```bash
# 1. Add a new user and vhost with a new cert
nginx-pool add alice blog.example.com --extend-cert

# 2. Add a reverse proxy for an internal service
nginx-pool reverse add myservice.example.com https://192.168.1.10 --no-ssl-verify --cert pool.glitchr.dev

# 3. Lock a site for maintenance
nginx-pool lock alice blog.example.com

# 4. Renew all certs (add to cron)
0 3 * * 1  /usr/local/bin/nginx-pool renew >> /var/log/nginx-pool-renew.log 2>&1
```

## Troubleshooting

| Symptom | Check |
|---------|-------|
| 502 Bad Gateway | `ls /home/$user/www/*.sock` — is the app socket present? |
| Wrong cert served | `nginx-pool ssl-map` → `nginx -t && systemctl reload nginx` |
| Reverse not taking effect | `nginx-pool reverse apply` — check `nginx -t` output |
| `--extend-cert` lost SANs | Run `nginx-pool certs <user>` before and after to compare |
| `make install` breaks nginx | `nginx -t` before applying; the Makefile runs `nginx -t` automatically |

Nginx error log: `/var/log/nginx/error.log`  
Access log: `/var/log/nginx/access.log`
